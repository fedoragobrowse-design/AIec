# Bug hunt, 2026-10-01

Findings from reading and from running the system, with the evidence that
separates a source-backed candidate from a reproduced defect. Reproduced items
say how they were reproduced and what now proves the fix.

## Reproduced and fixed

### A Docker sandbox could make its own workspace impossible to reclaim

**Where.** `crates/aiec-runtime/src/docker.rs`, `create` and `destroy`.

**What.** The workspace is bind-mounted `0o777` so a container can write to it,
and the container ran as root. Everything the guest created there was therefore
`root`-owned on the worker host, and `destroy`'s `remove_dir_all` failed with
`EACCES` on the first directory the guest made. The worker kept that state
directory forever, and the guest decided when and whether this worker could
reclaim its own disk - one leaked directory per sandbox, for as long as the
cluster ran.

**Reproduced.** `real_docker_listing_is_independent_of_descendant_contents`
failed in cleanup with `Permission denied`, and the tree on disk showed
`drwxr-xr-x root:root .../workspace/data` beside a `drwxrwxrwx` workspace the
worker owned.

**Fixed.** The container now runs as the worker's own uid and gid, so anything it
creates is reclaimable by construction. `destroy` also restores owner access
before removal, which covers a directory a previous version left behind, and a
failure that survives that is reported as a named cause rather than a bare
errno. Verified: 4/4 real-Docker tests, including the hundred-container churn
test that would show a state leak.

### Artifact groups accepted a file that changed mid-group

**Where.** `crates/aiec-core/src/runtime.rs` (the `get_file_chunks` trait
default) and `crates/aiec-api/src/worker.rs` (the `file_chunk` handler).

**What.** The first artifact burst of a file is read with
`expected_version = None`, by construction: the caller has no version to pin
yet. Every chunk in that burst was therefore validated independently. A guest
that rewrote or replaced a 128 KiB file with different same-length content
between two completed chunk reads produced a group that validated per chunk and
carried the first half of one file and the second half of another.
`HttpWorkerClient` assigned the *last* chunk's version to every frame it
reconstructed, so the consumer saw one consistent version, and storage's
checksum authenticated the hybrid it had been handed. The run succeeded and the
stored artifact was corrupt.

**Reproduced.** `a_group_read_refuses_a_file_replaced_between_its_chunks` in
`aiec-core` failed with chunk 0 served from inode 596741 and chunk 1 from inode
596847 under one successful group, on a real temporary file replaced by a
staged write and rename. `a_worker_group_read_across_a_replacement_is_refused`
and `a_worker_refuses_a_group_whose_chunks_disagree` failed in `aiec-api`: the
first because the worker relayed the hybrid, the second because a runtime that
overrides `get_file_chunks` can return any group it likes and the worker
encoded it.

**Fixed.** The first chunk's version *and* size are pinned for the rest of the
group in the trait default, so a replacement between completed chunks fails the
read itself; the size check additionally covers runtimes whose version stamp
does not include size. The worker validates every chunk against its own burst
step and requires the whole group to agree on size and version before building a
body, and takes the group's size and version from the first chunk rather than
relabelling the last. Verified: 6/6 core chunk tests and 31/31 worker tests.

### A lost event journal could be released back into service

**Where.** The Guard gateway's audit path.

**What.** A journal append failure set the same `cut` flag that an operator
release clears, so once the journal became writable again an ordinary release
reopened traffic while the authoritative evidence for the cut was missing. The
regression test failed with a real request reaching the upstream mock after the
journal had failed.

**Fixed.** A service or audit fault is latched and terminal. `health` reports
it, a release is refused while it is latched, and recovery requires a new
gateway after a verified journal replay rather than an operator's ordinary
network release. A release request now reaches its durable audit record before
traffic is permitted again, and a cut that lands in between fences the release
out.

### Docker workspace capture followed a guest-swapped symlink into the worker host

**Where.** `crates/aiec-runtime/src/docker.rs`, `collect_workspace`.

**What.** The capture checked a workspace entry's type with `symlink_metadata`
and then read it by path with `std::fs::read` or descended it with `read_dir`.
A guest that keeps running holds the same writable bind mount, so it can replace
an accepted regular file with a symlink to a host path in the window between the
check and the read. Host-readable bytes then land in a tenant snapshot, and a
restore or file download hands them back to the tenant. Static symlink
rejection does not help: the entry is a regular file when it is checked. The
lexical `strip_prefix` does not help either, because it never binds the later
open to the inode that was checked. Snapshot digests verify the bytes that were
captured, not where they came from.

**Reproduced.** `a_file_swapped_for_a_host_link_after_the_check_is_not_captured`
and `a_directory_swapped_for_a_host_link_after_the_check_is_not_captured` fail
with `host bytes were captured at /workspace/probe`, using a barrier that
arrests the walk after the type check and swaps the entry underneath it.

**Fixed.** The walk is descriptor-relative: each component is opened with
`O_NOFOLLOW`, classified from `fstat` on the opened descriptor rather than from
the path, and re-checked after opening. A link answers `ELOOP` or `ENOTDIR` and
is refused, and a component that stopped being a directory is refused as a
change rather than described as a link it is not.

### A snapshot buffered a whole guest file before enforcing the archive budget

**Where.** The same function, regular-file branch.

**What.** `std::fs::read` allocates the file's whole logical length before the
64 MiB budget is compared, and the allocation is in the worker process, outside
the container's memory cgroup. A sparse file makes the attack cheap for the
guest: 512 MiB of logical length costs almost no disk and a full worker buffer.

**Reproduced.** The child-process measurement reported
`outcome=limit-exceeded bytes_read=536872577` for a 512 MiB sparse file: the
budget was enforced, but only after the entire file had been read.

**Fixed.** The size is read from the opened descriptor and compared against the
archive's remaining budget *before* any allocation, and the read stops one byte
past the budget so a file that grows under the walk is refused rather than
truncated. The same measurement now reports `bytes_read=1665` for the same
512 MiB file.

### A directory listing failed on the contents of files it does not return

**Where.** `crates/aiec-runtime/src/docker.rs`, `list_files`.

**What.** Listing downloaded a recursive content archive and then extracted only
immediate-child names, subject to a 32 MiB cap on the whole download. Three
legitimately small files - each below the 16 MiB per-file limit - total more
than the cap, so a valid directory returned `limit_exceeded` instead of its three
entries. A large subtree below a directory had the same effect on its parent's
listing.

**Fixed.** Listing answers from the workspace bind mount directly: one
descriptor-relative open, immediate-child names, and one `fstat` per entry. No
file contents are downloaded, so a listing's cost is the number of entries
rather than the size of the tree below it.

Three behaviours changed with that fix, all deliberate:

- Listing answers from the bind mount rather than asking the daemon, so it no
  longer needs the container to be running - a paused sandbox can still be
  listed - and it never transfers file bodies to answer a question about names.
- A workspace path whose component is a link is refused for listing, where the
  daemon's archive walk used to follow it. This matches both
  `FileChunkRequest::read_workspace` and capture, which already refused links. A
  link *within* a listed directory is still reported, as a non-directory, so one
  socket or fifo cannot empty its neighbours out of a listing.
- Capture sorts its entries, so one workspace yields one set of archive bytes
  rather than whatever order the filesystem happened to return.

### A link traversal reported a raw errno

**Where.** `open_workspace_directory`.

**What.** With `O_DIRECTORY` set, a symlink answers `ENOTDIR` rather than
`ELOOP`: the kernel refuses the target type before `O_NOFOLLOW` is consulted. So
the link case fell through to a bare `io error: Not a directory`, which tells a
caller nothing about a workspace the guest controls.

**Fixed.** `ENOTDIR` names the link; `ELOOP` remains the general link case.

## Reported, not yet dispositioned

- Whole-run deadline cleanup overrides a requested retention, and concurrent
  expiry passes can leave a false cleanup-failure report behind a sandbox that
  was in fact destroyed (`crates/aiec-api/src/runs.rs`). Source-backed; needs a
  reproduction before any change.
- A guard policy selection is refused for any runtime other than Firecracker.
  That is intentional - there is no weaker fallback - but it means the Docker
  workspace defects above were reachable on the unguarded path until they were
  fixed.
