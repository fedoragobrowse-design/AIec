Computers for AI agents.

An agent needs somewhere to run code that nobody else can reach and nobody has to clean up. AIec hands it a real machine — its own kernel, its own filesystem, its own network — and takes it away when the work is done.

AIec is open source and self-hosted. There is no hosted version and no hosted API: the control plane, the workers and the sandboxes run on hardware you choose. Clone it, run it on a machine with KVM, and point your agent at it.

Isolation you can point at

Public workloads run on Firecracker microVMs. Each sandbox gets its own guest kernel, its own root filesystem, and a network namespace whose egress policy blocks the host LAN, RFC1918 ranges, link-local and cloud metadata addresses, the control plane, and other tenants. The guest control channel is a vsock socket that never touches the network.

Disposable by default

A sandbox is leased from a scheduler, billed to your own accounting while it runs, and destroyed when you are done. Snapshots restore a workspace onto a different worker after a failure, fenced by a monotonic generation so a superseded owner is rejected.

Yours to operate

PostgreSQL for metadata, S3-compatible storage for artifacts, and your own KVM hosts. You choose the capacity, the retention, and the blast radius. Nothing you run is metered by anyone else.

Bring your own agent

The local MCP server hands any MCP-capable coding agent a disposable machine, and can run a coding agent in a clean sandbox or compare two revisions of one, each side isolated.

Built on a published design

The architecture follows DeepSeek Elastic Compute (DSec) — “A Sandbox Infrastructure for Effective Agentic Training at Scale”, DeepSeek-AI & Tsinghua University, 2026 (arXiv:2609.22978). DSec argues that agent workloads arrive in bursts, need heterogeneous isolation, and keep state across long interactions — which calls for an elastic execution platform rather than a single sandbox runtime. AIec implements the parts of that which survive contact with a small team.

Cloud, later

A hosted AIec is something we may offer eventually. It is not what exists today and nothing on this site depends on it. If it happens, the interface will be this one: the same API, the same SDK, the same runtime model, running on somebody else's machines. The source will stay open either way.

No invented numbers

Benchmarks, throughput and latency figures are in the documentation only when they have actually been measured. If it is not measured, it is not claimed.
