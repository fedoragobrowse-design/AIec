Not yet implemented

Stated plainly so nobody plans around them:

  • Per-tenant snapshot and persistent-storage byte quotas. Per-request size ceilings exist; aggregate accounting does not yet.
  • A control-plane lifetime reaper observed firing in a live run. For guarded sandboxes the ceilings and expiry are durable control-plane state and a worker restart cannot reset them; the reaper that acts on an expired budget is implemented and database-tested, but we have not watched it fire end to end.
  • Method and path policy without TLS interception. In the default SNI mode Guard sees the hostname and forwards the tunnel; method and path rules require the operator to enable interception and acknowledge that Guard then holds a key able to read what it forwards.
  • Multi-host validation with separate control and worker machines. Same-host multi-worker recovery is proven; genuinely distributed operation is not yet.
  • An audit log viewer in the dashboard. Events are recorded, the UI is not built.
  • Usage is recorded but not billed. Every metric is exported for your own capacity planning; there is no payment path.

Hosting model

AIec is open source and self-hosted. There is no hosted execution capacity and no cloud provider in the path: the control plane, the workers and the sandboxes are the ones you deploy. What is claimed below is what runs on hardware you control.

ClaimStatus
AIec native Firecracker runtimeComplete and verified

Hosted capacity from a providerDoes not exist, by design
